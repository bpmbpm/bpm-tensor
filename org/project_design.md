## project design
Некоторые рекомендации по оформлению предложений в проекте [bpm-tensor](https://github.com/bpmbpm/bpm-tensor/)
### naming
- file имена файлов лучше именовать на английском и без пробелов, иначе в ссылки на них длинные и непонятные
- markdown ключевые заголовки (еа которые планируется ссылаться) лучше именовать на английском (можно с пробелами), тогда ссылки на них будут читаемые
- иллюстрировать лучше на mermaid (встроенная поддержка у github), при необходимсоти можно добавить плагин drawio, но он будет визуализироваться на github.io
- если иллюстрации в pgn, svg, jpg и т.п., то добавляем папку pic и там размещаем со ссылкой на вложенную папку (pic).

### formula
часто ИИ делает:
```
[
z=x+y
]
```
для github нужно 
```
$$
z=x+y
$$
```
$$ - до и после строка  
или 
$z=x+y$

### mermaid
частая ошибка - в нащзвании стоит ( ), т.е. mermaid это понимает как собственный символ
